# Web Scaffold + Design System — Design Specification

- **Date:** 2026-11-17
- **Status:** Draft (brainstormed, pending implementation plan)
- **Sub-project:** Frontend #1 — the React web app scaffold, design system, API client, routing, app shell, and message bus.

## 1. Context and Scope

This is the first of six frontend sub-projects. It establishes the foundation the other five (auth, projects/session tree, agents/providers UI, chat, MCP Apps) build on. The backend (`agentbox-api`) is complete and exposes a REST API + AG-UI SSE.

### 1.1 What this sub-project encompasses

- A standalone Bun + Vite + React + TypeScript app under `apps/web`.
- The **design system**: Bulma (layout) + Mantine (widgets) + RemixIcons, with light/dark synced to the system.
- **API client**: an OpenAPI-generated typed client with JWT injection.
- **Routing** with placeholder pages and an **app shell** (navbar + sidebar + content).
- A typed **message bus** (`mitt`).
- Server-state (TanStack Query) and client-state (Zustand) plumbing.
- A Vitest smoke-test harness.

### 1.2 Boundaries (out of scope, later sub-projects)

- Real auth/login flow (sub-project 2).
- Projects/session tree, agents/providers forms, chat, MCP Apps.
- Avatar generation, Mermaid, speech-to-text, attachments.

### 1.3 Dependencies

- The FastAPI backend (for the OpenAPI schema; the app runs without it for the scaffold smoke tests).
- Bun toolchain.

## 2. Decisions and Rationale

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | `apps/web` is a **standalone Bun project**. | The Python Uv workspace is Python-only; the frontend needs its own JS toolchain without disturbing the backend. |
| D2 | **Vite SPA** (not Next.js). | The backend is a separate API; an SPA is the natural fit and avoids SSR complexity. |
| D3 | **Bulma = layout/typography/spacing; Mantine = complex widgets.** | Both are mandated by the spec; this split avoids style conflicts. Never apply both systems to one element. |
| D4 | **Theme synced**: Mantine `defaultColorScheme="auto"` drives Bulma's `data-theme`. | Keeps one source of truth while honoring both libraries' dark modes, following the system setting. |
| D5 | **OpenAPI-generated client** (`openapi-typescript` + `openapi-fetch`). | Type-safe calls that stay in sync with the FastAPI schema; idiomatic consumption of an OpenAPI backend. |
| D6 | **TanStack Query (server state) + Zustand (client state) + mitt (message bus).** | Standard, focused tools: caching/loading for server data, small global state, and the mandated cross-component bus. |

## 5. Design System

- **Bulma v1** (dark-mode aware): imported once in `main.tsx`; used for layout (`columns`, `container`), spacing, typography, and general structure.
- **Mantine provider**: `MantineProvider` with `defaultColorScheme="auto"`; `Notifications` and `ModalsProvider` mounted at the root for later use.
- **RemixIcons**: imported via `@remixicon/react` as icon components (e.g. `<RiAddLine />`).
- **CSS order**: Mantine core styles first, then Bulma, configured so Bulma's base does not clobber Mantine widgets; the rule is one styling system per element.
- **`ThemeSync`**: reads Mantine's computed color scheme and sets `document.documentElement.dataset.theme = "light" | "dark"` so Bulma follows the same system-driven theme.

## 6. API Client (OpenAPI-generated)

- `scripts/gen-openapi.py` imports `agentbox_api.app.create_app`, builds the app, and writes `.openapi()` to `openapi.json`.
- `bun run codegen` runs `openapi-typescript openapi.json -o src/api/schema.d.ts`.
- `src/api/client.ts`: `createClient<paths>({ baseUrl: import.meta.env.VITE_API_URL })` from `openapi-fetch`, with middleware that injects `Authorization: Bearer <token>` from the auth store when present.

## 7. App Shell + Routing

- `App.tsx`: `BrowserRouter` + `QueryClientProvider` + `MantineProvider` + `ThemeSync` + `Notifications` + `ModalsProvider`.
- `AppShell`: Bulma navbar (top) + sidebar (nav links) + content outlet.
- Routes (placeholder pages for now):
  - `/` → HomePage
  - `/login` → LoginPage
  - `/agents` → AgentsPage
  - `/providers` → ProvidersPage
  - `/projects` → ProjectsPage

## 8. Message Bus

- `src/lib/bus.ts`: a typed `mitt` emitter over an `AppEvents` map (empty/extension-ready now). Used later for cross-component messages (e.g. session selection, theme changes).

## 9. State & Config

- `QueryClient` with sane defaults (retry once, stale-time).
- `useAuthStore` (Zustand): `token`, `setToken`, `clear` — placeholder consumed by the API middleware and (later) route guards.
- `VITE_API_URL` env (default `http://localhost:8000`).

## 10. Testing

- Vitest + Testing Library:
  - App renders the shell (navbar + sidebar).
  - Router renders a placeholder page for a route.
  - `ThemeSync` sets `data-theme` on `document.documentElement`.
- No backend required for these smoke tests (API client is configured but not exercised).
