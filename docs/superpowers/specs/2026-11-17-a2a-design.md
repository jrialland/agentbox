# A2A (Agent2Agent) Adapter — Design Specification

- **Date:** 2026-11-17
- **Status:** Draft (brainstormed; approved scope)
- **Sub-project:** A2A adapter — expose designated agents (with an agent card) over A2A v1.0, authenticated by API keys, starting agentic sessions.

## 1. Context and Scope

The initial spec: "The A2A API - used via the authentication of an API key created in advance - allows starting an agentic session. Only certain agents must support the A2A protocol: specifically, those that have been designated as such and for which the user who created them has added a specific **agent card**." (`initial_spec.md:102-106`).

A2A = Agent2Agent protocol **v1.0**; the Python SDK is `a2a-sdk` 1.3 (`a2a.types`, `a2a.server.*`, Starlette/FastAPI routes).

### 1.1 What this sub-project encompasses
- Per-agent A2A endpoints (card discovery + JSON-RPC), only for agents with an agent card.
- Agent-card management (`GET/PUT/DELETE /agents/{name}/card`) + UI.
- API-key authentication on the A2A surface.
- An `AgentExecutor` adapting the harness (project/session per A2A context, streamed artifacts/status).
- Real A2A protocol tests via the SDK client.

### 1.2 Boundaries
- HTTP JSON-RPC transport only (no gRPC/REST transports).
- Configured workspace (`A2A_WORKSPACE`); no per-card workspace or project picking.
- No push notifications/webhooks (A2A `pushNotifications` capability disabled).

### 1.3 Dependencies
- `agentbox-api`; new dep `a2a-sdk[fastapi]>=1.3`.

## 2. Decisions and Rationale

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Use the official `a2a-sdk` (no homegrown protocol). | Mandatory compliance. |
| D2 | **Per-agent** endpoints `/a2a/{agent}/…`, only when the agent has a card. | Spec: only designated agents with a card. |
| D3 | API-key auth (`Authorization: Bearer`) with scope `sessions:create` on all `/a2a/*`. | "used via the authentication of an API key". |
| D4 | One harness session per A2A **contextId**; project at `A2A_WORKSPACE`, owner = the key's user. | Multi-turn context maps naturally to a session; reuse core storage. |
| D5 | Stream text as artifacts; tool calls as status messages. | Faithful A2A streaming via `TaskUpdater`. |
| D6 | Card stored in the existing `AgentCard` table; the server injects `supported_interfaces` + Bearer security. | Users write skills/description, not URLs. |
| D7 | Auth check inside the mounted A2A dispatcher (reading `scope["auth"/"user"]`). | Avoids middleware-ordering issues; reuses the global `AuthenticationMiddleware`. |

## 3. Backend

### 3.1 Agent-card endpoints (`routers/agents.py`, `agents:create`)
- `GET /agents/{name}/card` → the stored card (404 if none).
- `PUT /agents/{name}/card` → validate the body as an A2A `AgentCard` (`name`, `description`, `version`, `skills`, default input/output modes, capabilities); store it in the `AgentCard` row (upsert). The server overrides `supported_interfaces` and security at serve time.
- `DELETE /agents/{name}/card` → delete the row (un-designates).

### 3.2 Per-agent A2A endpoints
Mounted at `/a2a` by a dispatcher ASGI app:
- Resolve `{agent}` from the path; 404 if the agent has no card.
- **Auth:** require `scope["user"].is_authenticated` and `sessions:create` in `scope["auth"].scopes` → else 401/403.
- Set a contextvar with the authenticated user id (for project ownership), then delegate to a cached per-agent Starlette app built with:
  - `create_agent_card_routes(card)` → `GET /a2a/{agent}/.well-known/agent-card.json`,
  - `create_jsonrpc_routes(DefaultRequestHandler(agent_executor, InMemoryTaskStore(), agent_card), "/")` → `POST /a2a/{agent}/`.
- The served card has `supported_interfaces=[AgentInterface(protocol_binding="JSONRPC", url=f"{A2A_PUBLIC_URL}/a2a/{agent}", protocol_version="1.0")]`, `capabilities=AgentCapabilities(streaming=True)`, and a Bearer security scheme with `security=[{"bearer": []}]`.

### 3.3 Executor (`AgentboxA2AExecutor(AgentExecutor)`)
- `execute(context, event_queue)`:
  - `contextId` = `context.current_task.context_id` (or a new one); use it as the harness session id.
  - Find-or-create a `Project` at `A2A_WORKSPACE` (owner = contextvar user, else admin) and a `SessionRow` (agent = the card's agent); `SQLiteMessageLogStore`.
  - `TaskUpdater(event_queue, task_id, context_id)`; `update_status(WORKING)`.
  - Run the harness with `get_message_text(context.message)` and `head_id` = latest leaf.
  - Stream text chunks as `add_artifact(parts=[new_text_part(text=chunk)])`; tool calls as status messages; `update_status(COMPLETED)`.
  - Errors → `update_status(FAILED)` with the message.
- `cancel(context, event_queue)` → cancel the active run, `update_status(CANCELED)`.

### 3.4 Settings
- `A2A_WORKSPACE` (default `.`) — project root for A2A sessions.
- `A2A_PUBLIC_URL` (default `http://localhost:8000`) — base for card `supported_interfaces`.

## 4. Frontend

- Agents page: an **A2A** action per agent → a modal to view/edit `name`, `description`, `version`, and skills (JSON or simple rows), Save (PUT) / Remove (DELETE). Show an "A2A" indicator in the table for agents with a card.
- `endpoints.ts`/`queries.ts`: `fetchAgentCard`, `setAgentCard`, `deleteAgentCard`; invalidate the agents/agent-card queries.
- Regenerate `schema.d.ts`.

## 5. Testing

- **Backend pytest** (`tests/test_a2a.py`):
  - Card CRUD; only designated agents get endpoints (404 otherwise).
  - `/a2a/*` without a valid API key → 401; with a key lacking `sessions:create` → 403.
  - Card discovery returns the card with the injected interface URL.
  - **Real A2A protocol test**: create an API key (`sessions:create`) and a card-bearing agent (with the `test` provider); use the **a2a-sdk client** (against the ASGI app) to `message/send` and assert a completed task + text artifact; `message/stream` yields status/artifact events.
- **Frontend Vitest**: the A2A card modal renders/saves (queries mocked).
- **E2E** (`e2e/a2a.spec.ts`): create an agent, set its A2A card via the UI, then (from the test) call the A2A endpoint with an API key and assert a response; and confirm non-designated agents 404.

## 6. Error Handling

- 401 (no/invalid API key), 403 (missing scope), 404 (unknown/undesignated agent).
- Invalid card JSON → 422/400.
- Executor errors → task `FAILED`.

## 7. Open Items / Future Work

- gRPC / REST transports; push notifications; `extended_agent_card`.
- Per-card workspace / project binding.
- Card UI with a richer skill editor.
