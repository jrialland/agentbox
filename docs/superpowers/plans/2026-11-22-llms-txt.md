**Goal:** Serve a public, agent-facing Markdown guide at `/llms.txt` with focused section files under `/llms/`, matching the llmstxt.org convention.

**Architecture:** A new `agentbox_api.routers.llms` router serves package-data Markdown files from a fixed whitelist. The Vite dev server forwards the same URLs so browser-origin fetches behave like production.

**Tech Stack:** FastAPI/Starlette `Response`, pytest + httpx `ASGITransport`, Vite dev proxy, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-22-llms-txt-design.md`

## Global Constraints

- Python 3.11+; Ruff line length 100.
- Both routes set `include_in_schema=False`; do **not** regenerate `apps/web/openapi.json` or `apps/web/src/api/schema.d.ts`.
- The routes are public: no `require_permission` dependency and no `Authorization` header required.
- Responses are `Content-Type: text/markdown; charset=utf-8` with `Cache-Control: public, max-age=300`.
- Only filenames in the server-side whitelist are served; everything else is `404`.
- All examples use `$AGENTBOX_URL` and `$TOKEN`; never hard-code a host.
- Use the canonical domain vocabulary from `AGENTS.md`: agent configuration, session, subagent session. Do not write "spawn an agent" or "sub-agent".
- Do not pass multiple package test directories to one pytest invocation.

```python
import pathlib

from fastapi import APIRouter, HTTPException, Response

router = APIRouter(tags=["docs"], include_in_schema=False)

_LLMS_DIR = pathlib.Path(__file__).resolve().parent.parent / "llms"


def _markdown(name: str) -> Response:
    try:
        text = (_LLMS_DIR / name).read_text(encoding="utf-8")
    except FileNotFoundError:
        raise HTTPException(status_code=404, detail="Not found") from None
    return Response(
        content=text,
        media_type="text/markdown; charset=utf-8",
        headers={"Cache-Control": "public, max-age=300"},
    )


@router.get("/llms.txt")
async def llms_index() -> Response:
    return _markdown("llms.txt")
```

````markdown
# Authentication

The `/llms.txt` and `/llms/*.md` files, `/openapi.json`, `/docs`, and `/sandbox` are public. `POST /auth/login` and `POST /auth/register` are also public. All other API routes require a bearer credential.

## JWT login

`POST /auth/login` with JSON:

```json
{"username": "admin", "password": "admin"}
```

The response is `{"access_token": "<jwt>", "token_type": "bearer"}`. Send it on every request:

```bash
curl -sS "$AGENTBOX_URL/auth/me" \
  -H "Authorization: Bearer $TOKEN"
```

JWTs expire after the configured lifetime (default one hour). Log in again when the API returns `401`.

## API keys

Personal API keys are long-lived bearer credentials. Create one with an authenticated JWT:

```bash
curl -sS -X POST "$AGENTBOX_URL/api-keys" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"scopes": ["sessions:read", "sessions:create"], "expires_at": "2026-12-31T00:00:00Z"}'
```

The raw `key` is returned once; store it. Use it exactly like a JWT:

```bash
curl -sS "$AGENTBOX_URL/sessions" \
  -H "Authorization: Bearer $TOKEN"
```

`scopes` must be a subset of the scopes held by the user creating the key. `expires_at` is optional but must be in the future. Revoke a key with `DELETE /api-keys/{id}`.

## Scopes and errors

A credential carries permission scopes such as `sessions:create`, `agents:read`, or `providers:create`. Each route checks its own scope.

- `401 Unauthorized`: missing, expired, revoked, or invalid credential.
- `403 Forbidden`: valid credential without the required scope.
- `GET /auth/me` returns the current user id, username, and scopes.
````

````markdown
# Quickstart

This walkthrough takes an agent from no credentials to a streamed turn. Set the origin and a token first:

```bash
export AGENTBOX_URL=http://localhost:8000
export TOKEN=<jwt or api key>
```

## 1. Authenticate

```bash
curl -sS -X POST "$AGENTBOX_URL/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin"}'
```

Copy `access_token` into `TOKEN`. For a long-lived credential, create an API key as described in [Authentication](/llms/authentication.md).

## 2. Check models

```bash
curl -sS "$AGENTBOX_URL/providers" -H "Authorization: Bearer $TOKEN"
curl -sS "$AGENTBOX_URL/models" -H "Authorization: Bearer $TOKEN"
```

If the model you need is missing, create a provider and refresh or create its models:

```bash
curl -sS -X POST "$AGENTBOX_URL/providers" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "deepseek", "kind": "deepseek", "base_url": "https://api.deepseek.com/v1", "api_key": "<provider key>"}'

curl -sS -X POST "$AGENTBOX_URL/providers/<provider-id>/models/refresh" \
  -H "Authorization: Bearer $TOKEN"
```

A model label such as `smart` can be used instead of a model name if an administrator assigned labels.

## 3. Create a project

`path` must be an existing directory on the server that runs Agentbox.

```bash
curl -sS -X POST "$AGENTBOX_URL/projects" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "demo", "path": "C:\\work\\demo"}'
```

Keep the returned `id` as `PROJECT_ID`.

## 4. Create an agent configuration

Use exactly one of `model` or `model_label`. The `model` value is the model name from `GET /models`, not its id.

```bash
curl -sS -X POST "$AGENTBOX_URL/agents" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "assistant",
    "description": "Project assistant",
    "instructions": "You are a careful coding assistant.",
    "model": "deepseek-chat",
    "tool_bindings": [{"name": "read_file"}, {"name": "write_file"}],
    "mode_definitions": [
      {"name": "ask", "flags": {"write": false}},
      {"name": "agent", "flags": {"write": true}}
    ]
  }'
```

## 5. Create a session

The request field is named `agent_id`, but its value is the agent configuration **name**.

```bash
curl -sS -X POST "$AGENTBOX_URL/sessions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"project_id": "<project-id>", "agent_id": "assistant"}'
```

Keep the returned `id` as `SESSION_ID`.

## 6. Send a message and consume the stream

```bash
curl -N -X POST "$AGENTBOX_URL/sessions/$SESSION_ID/messages" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"content": "List the files in this project.", "mode": "agent"}'
```

The response is an AG-UI server-sent-event stream. Keep reading until `RUN_FINISHED` or `RUN_ERROR`; see [Streaming](/llms/streaming.md).

## 7. Read history

```bash
curl -sS "$AGENTBOX_URL/sessions/$SESSION_ID/messages" \
  -H "Authorization: Bearer $TOKEN"
```

The response is the active conversation leaf, oldest turn first.
````

````markdown
# Agents

An agent is a configuration record, not a running process. It defines the model, instructions, tools, and modes used when a session starts.

## Create an agent

`POST /agents` (permission `agents:create`):

```json
{
  "name": "assistant",
  "description": "Project assistant",
  "instructions": "You are a careful coding assistant.",
  "model": "deepseek-chat",
  "tool_bindings": [{"name": "read_file"}, {"name": "grep"}],
  "mode_definitions": [
    {"name": "ask", "flags": {"write": false}},
    {"name": "agent", "flags": {"write": true}}
  ]
}
```

Fields:

- `name` is required, unique, and cannot be changed by an update.
- `description` and `instructions` are free text. `instructions` is the system prompt and supports prompt templating; preview it with `POST /prompts/preview`.
- Use exactly one of `model` (a model name from `GET /models`) or `model_label` (an assigned label).
- `tool_bindings` selects native tools such as `read_file`, `write_file`, or `grep`, or MCP servers.
- `mode_definitions` defines named modes and their boolean flags; `ask` with `write: false` and `agent` with `write: true` are the usual pair.
- `plugin_mcp_bindings` selects MCP servers contributed by enabled plugins.

Remote MCP binding:

```json
{"server_url": "https://example.com/mcp", "id": "example"}
```

Local stdio MCP binding:

```json
{"id": "filesystem", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]}
```

## Update, read, delete

- `PUT /agents/{name}` (permission `agents:create`) replaces the configuration. The `name` in the body must match the path.
- `GET /agents` and `GET /agents/{name}` require `agents:read`.
- `DELETE /agents/{name}` requires `agents:delete`.

## Avatars and A2A cards

- `GET /agents/{name}/avatar` returns the avatar image; `PUT` uploads one as a multipart field named `file`; `DELETE` restores the generated avatar.
- `GET/PUT/DELETE /agents/{name}/card` manages the A2A agent card. Only agents with a stored card are exposed under `/a2a`.

## Skills

- `GET /skills` and `GET /skills/{name}` list available skills.
- `PUT /skills/{name}` and `DELETE /skills/{name}` manage user skills.
- Activate a skill for one turn with `"skill": "<name>"` in the session message body.
````

````markdown
# Sessions

A session is a live instance of an agent configuration on a project directory. It stores the conversation tree and run state. Child sessions started by the running agent are **subagent sessions**.

## Lifecycle

- `POST /sessions` with `{"project_id": "<id>", "agent_id": "<agent name>"}`. Despite the field name, `agent_id` carries the agent configuration name.
- `GET /sessions` lists root sessions. Subagent sessions have a parent and are not included.
- `GET /sessions/{sid}` returns project, agent name, title, and creation time.
- `PATCH /sessions/{sid}` renames a session with `{"title": "..."}`.
- `DELETE /sessions/{sid}` deletes the session and its data.

## History

`GET /sessions/{sid}/messages` returns the active leaf path, oldest turn first. Each turn includes `id`, `role`, `content`, `parent_id`, `created_at`, optional `context_tokens`, `activity`, and `attachments`.

Do not edit history. To branch or re-run, send a new message with `fork`, `fork_from_turn_id`, or `retry_turn_id` instead.

## Send a message

`POST /sessions/{sid}/messages` accepts:

```json
{
  "content": "List the files in this project.",
  "mode": "agent",
  "skill": null,
  "attachment_ids": [],
  "fork": false,
  "fork_from_turn_id": null,
  "retry_turn_id": null
}
```

- `content` is required.
- `mode` defaults to `agent` and must name a mode defined on the agent.
- `skill` activates one skill for this turn.
- `attachment_ids` references uploads from `POST /sessions/{sid}/attachments` (multipart field `file`).
- `fork: true` with `fork_from_turn_id` branches from that turn.
- `retry_turn_id` re-runs a user turn or the parent of an assistant turn without duplicating the user turn.

The response is `text/event-stream`; see [Streaming](/llms/streaming.md).

## Cancel

`POST /sessions/{sid}/messages/cancel` returns `202` with `{"status": "cancelling"}` when a run is active, or `409` when no run is active.

## Files, plan, and LSP

- `GET /sessions/{sid}/files?q=...` returns `{"files": [...]}` for the project root.
- `GET /sessions/{sid}/plan` returns `{"items": [{"id", "position", "content", "status"}]}`.
- `GET /sessions/{sid}/lsp` returns detected servers, active servers, and diagnostic snapshots.

## Attachments and MCP relay

- `POST /sessions/{sid}/attachments` uploads a file and returns `{id, media_type, filename}`.
- `GET /sessions/{sid}/attachments/{aid}` downloads it.
- `POST /sessions/{sid}/mcp/{server_id}/resources/read` with `{"uri": "..."}` reads an MCP App resource.
- `POST /sessions/{sid}/mcp/{server_id}/tools/call` with `{"name": "...", "arguments": {}}` calls an MCP App tool.

## Subagent sessions

A running agent starts child sessions with its tools: `list_agents`, `start_subagent_session`, `list_subagent_sessions`, `get_subagent_session`, `cancel_subagent_session`, `wait_subagent_session`, and `wait_subagent_sessions`. There is no REST endpoint that creates subagent sessions; use the agent's tools.
````

````markdown
# Streaming

A run streams over AG-UI server-sent events from `POST /sessions/{sid}/messages`.

## Request

```bash
curl -N -X POST "$AGENTBOX_URL/sessions/$SESSION_ID/messages" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"content": "Explain the project layout.", "mode": "agent"}'
```

`-N` disables client buffering. The response is `text/event-stream`; each `data:` frame is a JSON AG-UI event.

## Event lifecycle

A successful run starts with `RUN_STARTED` and ends with `RUN_FINISHED`. A failed run ends with `RUN_ERROR`. Between them, expect:

- `TEXT_MESSAGE_START`, `TEXT_MESSAGE_CONTENT`, `TEXT_MESSAGE_END` for assistant output.
- `REASONING_MESSAGE_START`, `REASONING_MESSAGE_CONTENT`, `REASONING_MESSAGE_END` for visible reasoning.
- `TOOL_CALL_START`, `TOOL_CALL_ARGS`, `TOOL_CALL_END`, `TOOL_CALL_RESULT` for tool activity.
- `STEP_STARTED` and `STEP_FINISHED` for loop steps.
- `CUSTOM` with name `mcp.warning` when an MCP server fails to start; the turn continues.

The assistant turn is persisted after the run reaches a terminal event. Consume the stream to completion before closing the connection so persistence can finish.

## Client rules

- Keep reading until `RUN_FINISHED` or `RUN_ERROR`; do not poll history while the stream is open.
- Treat `RUN_ERROR` as a failed turn and surface the error message.
- To stop a run, call `POST /sessions/{sid}/messages/cancel` rather than only closing the connection.
- Send one active message per session at a time.
````

````markdown
# Protocols

Agentbox exposes the same runtime over several protocols.

## AG-UI

## A2A

A2A exposes agents that have a stored agent card.

- Card: `GET /a2a/{agent}/.well-known/agent-card.json`
- JSON-RPC: `POST /a2a/{agent}`

Both routes require a bearer credential with the `sessions:create` scope and an agent with a card. An unauthenticated request returns `401`, a credential without the scope returns `403`, and an unknown agent or missing card returns `404`.

The card's interface URL is built from the server setting `a2a_public_url`; set it to the externally reachable origin when Agentbox runs behind a proxy.

## ACP

ACP is a stdio JSON-RPC protocol for IDEs. It is not an HTTP endpoint. Launch it with the `agentbox-acp` console script or `python -m agentbox_api.acp_server` and speak ACP over stdin/stdout.

## MCP

MCP servers are configured on the agent as remote URL or stdio tool bindings. API clients do not call MCP directly; the running agent does. The session endpoints under `/sessions/{sid}/mcp/...` exist only to relay MCP App requests to the UI.
````
